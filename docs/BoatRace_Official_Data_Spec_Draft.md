## 4. バイト位置の表記と解析原則

以下の位置はすべて **CP932の生バイト上の0始まり**。Pythonの `[開始:終了]` は終了位置を含まない。行頭・行末の空白を残し、CRLFだけを除いた状態で切り出す。

- Unicode文字列の文字位置と混同しない。
- 行全体に `strip()` や `rstrip()` をかけてから幅を測らない。
- 指定領域を切り出してからCP932で厳密にデコードする。
- 原表記と正規化後の値を分ける。数字欄の空白除去、コード判定、数値化は切り出し後に行う。

## 9. 取得・展開の実装方針（READMEを具体化した案）

### 9.1 日付と保存先

READMEで2026-09-02の取得時に確認したURL形式：

```text
https://www1.mbrace.or.jp/od2/B/{YYYYMM}/b{YYMMDD}.lzh
https://www1.mbrace.or.jp/od2/K/{YYYYMM}/k{YYMMDD}.lzh
```

B/KサンプルはKAZから受け取った原本を使用した。公式案内ページは今回オンラインで調査したが、追加のLZHは取得していない。B/K専用の公開時刻・全提供期間・欠測時の応答は未確定。公式画面の更新時刻との違いは第11.5節に記す。

設定から取得するデータルート配下に保存する。職場・自宅のドライブ文字を実装へ直書きしない。

```text
raw/boatrace_official/{program|result}/{YYYY}/{MM}/{b|k}{YYMMDD}.lzh
staging/boatrace_official/{program|result}/{YYYY}/{MM}/{b|k}{YYMMDD}/{B|K}{YYMMDD}.TXT
```

日付は完全な年月日として内部に保持し、ファイル名生成時にのみ2桁年へ変換する。対応する年の範囲は、公式の提供範囲を調べて決める。

### 9.2 ダウンロードと履歴

1. 日付と種別を検証し、URL・保存先を決める。
2. 正式ファイルがあれば再ダウンロード・上書きをしない。履歴との不一致や履歴欠落は別状態として記録する。
3. 一意な一時ファイルへ取得し、タイムアウト・サイズ・応答の成否を検査する。
4. SHA-256を計算する。HTTP成功だけで正しいLZHと断定せず、アーカイブ検査も行う。
5. 成功した一時ファイルを、既存ファイルを置換しない方法で正式名へ確定する。存在確認から確定までの競合も考慮する。
6. 取得・検査・失敗・スキップを履歴へ残す。正式ファイルと履歴の片方だけが残った場合は再照合できるようにする。

履歴項目案：種別、対象日、URL、開始・終了時刻（タイムゾーン付き）、HTTP状態、バイト数、SHA-256、保存先、処理結果、失敗理由、試行回数、プログラム版、設定識別情報。時刻はUTC等で一貫して保存し、KAZ向け表示はJSTとする。

大量アクセス・無制限再試行は行わない。具体的な回数・待機時間・タイムアウト・サイズ上限・並行実行制御・履歴保存形式は実装前に決める。HTTPエラーを直ちに非開催と分類しない。

### 9.3 展開

1. `7z l -slt`相当で内部パス・サイズ・方式を検査する。絶対パス、親ディレクトリ参照、想定外ファイルなどを検出する。
2. `7z t`相当で整合性を検査する。終了コードと出力を保存する。
3. 隔離した一時展開先へ展開し、展開後サイズ・ハッシュ・内部ファイル名・文字コードを検査する。
4. 成功時に`staging`の正式保存先へ確定する。既存展開物を上書きしない。
5. 異常時は失敗として記録し、途中生成物を成功した展開物と混同しない。

手動作業では未存在の展開先と`-aos`を併用した。本番では`-aos`によるスキップと終了コード0だけで新規展開成功と判定せず、出力ファイルの検証を行う。

## 10. 蓄積に引き継ぐ設計事項

- 主キー候補：レースは対象日・会場コード・レース番号、選手成績はさらに艇番。登録番号も別項目で保持する。
- 艇番・着順・進入を別々に扱う。尼崎5Rでは艇番と進入が異なる艇がある。
- 成績状態、展示、スタート、レースタイムは原表記と正規化値を分ける。変換できないものを0にしない。
- 未知コード・長さ違い・未解析行を黙って捨てず、元ファイルハッシュ、行番号、原行とともに追跡する。
- 払戻は１レース・１券種・複数組の構造として扱う。券種ごとに単一の勝ち組へ固定しない。
- 成績・払戻・決まり手など結果判明後の項目と、予測時点で取得済みの情報を分離する。
- Kに展示・気象が含まれていても、そのKファイルから得た値を予測時点で取得済みだった証拠にはしない。予測時の利用には別途取得履歴・利用可能時刻の管理が必要。
- 本資料の位置とルールにはバージョンを持たせる。新しいサンプルで差異を確認したら、原本を残して解析仕様を更新する。

## 11. 公式説明の調査結果と適用判断

確認日：2026-09-05。以下では、公式の説明そのものと、それをサンプルへ適用する本プロジェクトの判断を区別する。別の公式データ商品・画面の説明を、B/Kのバイト仕様として転用しない。

### 11.1 着順・状態コード

[ボートレース三国公式サイト](https://www.boatrace-mikuni.jp/)は「三国専属記者の直前予想」へリンクしている。そのリンク先の[データページの注記※2](https://www.mikuniks-web.jp/races)に、同ページで使用する記号の意味が明記されている。

| コード（正規化後） | 凡例が示す意味 | 今回のKでの観測 |
| --- | --- | --- |
| `S0` | 選手責任外の失格 | 3行 |
| `S1` | 選手責任の失格 | 9行 |
| `K0` | 選手責任外の欠場 | 1行 |
| `F` | フライング | 原表記`F `が1行 |

同じ凡例には `S2`（他艇を妨害）、`L1`（選手責任の出遅れ）、`K1`（選手責任の欠場）もある。今回はこの3コードのKサンプルを未観測。`L0`についてはこの凡例での対応確認はできていない。

これは公式サイトが案内する記者データページの凡例であり、B/Kのフォーマット仕様書そのものではない。本プロジェクトでは、今回一致する4コードの状態ラベルに採用し、原行・原コードを必ず残す。`S1`を転覆と決めつけず、具体的な失格原因と責任区分を混同しない。

[BOAT RACE公式「フライング・出遅れ」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_01_01_04.html)でも、規定時刻より早い通過がF、1秒以上遅い通過がLと説明される。したがって、`F0.01`を通常の正のST `0.01`に変換しない。初期実装では原表記と状態を保存し、符号付き数値化の規則は別途定義する。同ページの罰則日数等は2022年時点の説明なので、現在の罰則仕様として本資料には採用しない。

[2017年前期級別決定の公式発表](https://www.boatrace.jp/owpc/pc/site/news/2016/11/492/)には、責任外の失格・欠場等の`S0,L0,K0`を出走回数から除外するとある。過去の審査に関する根拠であり、現在の全指標を再計算する完全規則ではない。将来、出走回数・事故率・勝率を再集計する際は、その対象期間に適用される規則を別に確認する。

### 11.2 勝率・2連対率・集計期間・級別

[公式「レーサーの勝率（全国・当地）」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_01_01_05.html)では、勝率は着順点の総和を出走数で割った値。全国は各場を通した成績、当地は当該レース場の成績を指す。勝率5.14を勝つ確率51.4%と解釈しない。

[公式「複勝率」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/jiten/28/y_235.html)は、2連対率を1・2着回数の合計÷出走回数×100と説明する。[公式「モーターとボートの成績」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_01_01_06.html)も機材の成績を2連対率として説明している。本プロジェクトではBの「2率」をこの意味で扱い、原値を百分率として保持する。必要な時にだけ100で割り、予測確率とは別の過去集計特徴量にする。

[公式「本サイトについて」](https://www.boatrace.jp/owpc/pc/extra/about.html)の出走表画面の説明を要約すると次のとおり。

| 項目 | 公式画面の説明 |
| --- | --- |
| 全国 | 開催初日の属する月を含めた6ヶ月。今節分は除外 |
| 当地 | 開催初日を24ヶ月戻した日付が属する年の元日から、前検日の前日まで。今節分は除外 |
| モーター・ボート | 使用開始から通算、最長1年。今節分は除外 |
| 出走表の体重 | 場で測った最新値 |
| 直前情報の体重 | 当日の直前値 |

これらは公式画面の説明であり、Bの集計期間・丸め・体重の整数表示との一致を保証する記述ではない。Bの再集計や小数体重の補完には未適用とする。

[公式「級別審査」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/jiten/07/y_048.html)では、5～10月の審査が翌年1～6月、11～翌4月の審査がその年7～12月の級別へ適用される。Bにある級別は対象日時点の値として保存し、後の級別で上書きしない。

### 11.3 早見・今節成績

[公式「早見」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/jiten/26/y_212.html)は、1日に2回出走する選手の、もう一方のレース番号を示すと説明する。[公式「早見レース・他レース」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_01_01_09.html)では、空欄は1回出走と説明される。Bの726行の相互照合と合わせ、早見はnullableな別レース番号として採用する。後発レースだけに制限しない。

[公式「今節の成績」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_01_01_08.html)は、開催中の節における成績と、1日2走の表示を説明している。ただし、掲載例は着順・進入・STを含む画面であり、Bの12バイト領域と同じ形式ではない。Bの各バイトの日付・出走順対応と`S/F`の変換は未確定のまま、原領域を保存する。

### 11.4 払戻金とオッズ

[公式「配当金」](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/jiten/26/y_207.html)は100円購入時の金額を基準に説明している。Kの払戻欄はこの定義を採用し、`payout_per_100_yen`のように基準を明示した整数円で保存する。的中時の受取額は購入額÷100×払戻金とし、利益と区別する。返還・特払い・同着等は別の精算規則が必要で、今回の通常払戻の調査だけでは網羅しない。

[公式「オッズの見方」](https://www.boatrace.jp/owsp/sp/extra/enjoy/guide/level2/l2_01_03_01.html)は、購入時の倍率と最終の配当が一致するとは限らないと説明する。さらに[本サイトについて](https://www.boatrace.jp/owpc/pc/extra/about.html)は、締切時オッズがスタート事故等を反映する最終確定値ではないと区別する。Kの払戻金÷100は結果側の倍率であり、購入判断時のオッズの代用にはしない。

人気欄の意味の一般的な説明はあるが、今回の調査ではKの順位の計算方法・同順位処理・返還後の扱いまで特定できなかった。初期実装は人気原値を保存するところまでとし、最終オッズから独自に順位を再生成しない。

尼崎6R等の複勝が1組だけである理由、Bの当地0.00と未出走・未集計の区別は引き続き未確定。該当値を推測で補わない。
